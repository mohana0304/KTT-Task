database:
    is just an organized collection of data stored on a computer
    data is arranged in tables
    


Relational Databses:
    A relational database is based on the concept of a relation (from mathematics):
        Table (Relation) → A structured dataset
        Row (Tuple) → A single record
        Column (Attribute) → A property of that record

    key concept:
        primarykey -uniquely identifies each Row
        foreign key - connects one table to another
        Relationships - One-to-One → One user → one profile
                        One-to-Many → One customer → many orders
                        Many-to-Many → Students ↔ Courses (via join table)
        schema(structure) - defines tables,columns,datatypes,constraints in relational databases
                            schema is strict and predefined
        ACID Properties - Atomicity → Transaction succeeds fully or fails fully
                          Consistency → Data always follows rules
                          Isolation → Transactions don’t interfere
                          Durability → Data is permanently saved
        
    Benefits:
        strong data integrity - constraints prevent invalid data (No duplicate primary keys ,foreign key must exist) 
        structured & Organized - fixed schema ,Easy to understand Relationships
        Powerful Querying(SQL) - join multiple tables, Aggregate data(SUM,COUNT),filter with conditions
        Transaction support (ACID)
    Limitations:
        Rigid schema - structure must be defined in advance, changing schema later is difficult
        scaling issues - vertically → bigger server (RAM/CPU)
        performance  with large joins - JOIN operations become slow on massive datasets, complex queries can degrade performance
    
SQL - structured,relational,strict
NoSQL - flexible,scalable,less Rigid

SQL :(Structured Query language)
    is a language used to communicate with databases.
    this store data in tables with predefined schema and Relationships.
    eg: (MySQL,PostgreSQL,Oracle database)

    fixed schema, Table based structure, strong consistency,powerful Querying

NoSQL :
    this are designed for flexibility and scalability
    eg: MongoDB(document),Redis(key-value),Apache cassandra(column),Neo4j(graph)
    
    flexible schema,different data Models (document,key -value, column family,graph)
    Horizontal scalability - Easily distributed across many serevers

data constraints:
    this are rules applied to table columns to ensure
    data is valid
    data is consistent
    relationships between tables are maintained

    primary key - uniquely identifies each row 
                  cannot contain NULL 
                  cannot have duplicate values
    foreign key - link one table to another 
                  Ensures referential integrity
    unique - prevents duplicate values
             allows NULL(depend on DB)
    NOT NULL - column must have a value
               cannot be empty
    check - enforces custom rules
    

JOIN:
    inner join - return only matching rows between both tables
    left join - all rows from left table 
                matching rows from RIGHT
                no match->NULL
    right join - all rows from right table
                 matching rows from left 
                 no match->NULL
    full outer join - all rows from both tables
                      match where possible
                      else ->NULL
                     

scalar subquery 
        select name,salary from employees where salary > (select avg(salary) from employees);
        inner query -> return one value
        outer query compares each row

column subquery
        return one column multiple rows
Row subquery
        return one row with  multiple columns
table subquery
        return a full table

Types of subquery
        1. Non-correlated subquery -independent query (runs once)
                select name from employees where salary > ( select avg(salary) from employees);

        2. correlated subquery - depends on outer query (runs per row)
                select name from employees e where salary > ( select avg(salary) from employees where dept=e.dept);

Nested subqueries 
    subquery inside another subquery

special subquery operators
    in
    exist
    any
    all

Transaction
    is a set of sql operations esecuted as one unit
    BEGIN (Start Transaction)
    COMMIT (Save Changes)
    ROLLBACK (Undo Changes)
    SAVEPOINT (Partial Rollback) - Allows rollback to a specific point
    ACID Properties (Very Important) - These ensure reliable transactions
        A – Atomicity (All or Nothing) Either all queries run OR none
        C – Consistency  Database remains valid before & after
        I – Isolation  Transactions don’t interfere with each other
        D – Durability  Once committed → data is permanent (even after crash)


1. Atomicity (All or Nothing)
    If one fails → everything rolls back

2. Consistency (Valid State)
     Data always follows rules (constraints)

3. Isolation (No Interference)
    Transactions don’t affect each other

4. Durability (Permanent)
    Once committed → data is saved permanently

create table students(
student_id int primary key,
name varchar(10),
age int,
city varchar(10),
admission_date date
);

CREATE TABLE courses (
    course_id INT PRIMARY KEY,
    course_name VARCHAR(100),
    fee DECIMAL(10,2)
);

CREATE TABLE enrollments (
    enroll_id INT PRIMARY KEY,
    student_id INT,
    course_id INT,
    marks INT,
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
